# Project guidance

Consult `DECISIONS.md` when revisiting a project choice, investigating why
something exists, or considering an approach previously rejected. Check current
source and tests as well: the decision log records intent, not live behavior.

Record consequential decisions and their rationale in `DECISIONS.md`, including
relevant alternatives or constraints. Update existing entries when decisions
change rather than leaving conflicting guidance. Keep it concise; routine
configuration changes and values already clear from code do not need entries.

Inspect relevant source before editing, make focused changes, and run the most
relevant validation available. Report any verification you cannot perform.
